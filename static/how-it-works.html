The data flow

Simple inputs. Clear validation. Local records.

StrideSignal currently focuses on the first step of a larger research system: collecting consistent wearable readings and making them easy to inspect.

01
Collect

Enter or send a sample

Use the dashboard form for individual samples, or send JSON to the acquisition API. Device-specific Bluetooth pairing is not included yet.

Go to data dashboard →
02
Validate

Check data quality

Each record needs a participant and device ID, timezone-aware timestamp, three acceleration axes, and three angular-velocity axes. Heart rate is optional.

Units: m/s² · rad/s · bpm
03
Store & review

Keep a local record

Validated readings are stored in SQLite. The dashboard lists recent entries and can filter them by participant ID.

Local host · SQLite storage
What this prototype does not do

Collection is not a risk assessment.

There is no injury-risk model, diagnosis, clinical interpretation, wearable connection, user authentication, or production health-data protection in this prototype. Any future risk engine would need suitable evidence, validation, and expert review before it could be responsibly evaluated.

For developers

Acquisition API

Single-reading and batch endpoints accept validated JSON. Batch imports reject the whole batch when any reading is invalid.
